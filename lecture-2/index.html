01 / Foundations

Why bother managing data?

Every business runs on data: customer names, prices, orders, salaries. Data Resource Management (DRM) is simply the practice of treating that data as a valuable company asset, on purpose, instead of letting it pile up randomly in spreadsheets and files.

In one line: Data Resource Management is a managerial activity that uses technology (databases, data warehousing) to keep a company's data accurate, organized, and useful for the people who need it.
Analogy: think of data like money. If you throw cash in random drawers around the house, you lose track of it. A bank (the database) keeps it in one safe place, organized, with rules about who can touch it. DRM is running your data like a well-managed bank.
💎

Data is an asset

Well-managed data becomes a competitive advantage, not clutter.

📊

Better decisions

Clean, joined-up data powers reports and analytics.

🧮

One version of truth

Everyone sees the same correct numbers.

🛡

Control & trust

Better security, privacy, and compliance.

02 / Foundations

The logical data hierarchy

Data is built up in layers, from the tiniest piece to the whole database. Understanding these five words is the foundation of the entire chapter.

The five levels: a character is one symbol → a field is one fact → a record is one thing fully described → a file/table is many records of the same kind → a database ties related files together.
Analogy: letters spell a word (field), words fill an ID card (record), a stack of ID cards is a class list (file), and all the school's lists together are the school database.

03 / Approaches

File processing vs the database approach

Before databases, every program kept its own private files. That sounds harmless, but it quietly causes four big problems. Flip the switch below to see the difference.

Old way (file processing): each app has its own files. Modern way (database approach): all apps share one database through a DBMS.
Interactive · flip the switch
File processingDatabase
File processing: the same customer is stored three times (in red).

⚠ Problems

Why it matters: if the customer changes their phone number, file processing forces you to update it in three places, and you will forget one. A shared database stores it once, so it is always right.
04 / Approaches

The DBMS: the engine in the middle

You never talk to a database directly. You talk to a Database Management System (DBMS), the software that sits between people (and apps) and the stored data.

DBMS = Database Management System. The software interface that creates databases, keeps the data clean, and answers requests for information. Examples you may know: Oracle, MySQL, Microsoft SQL Server, PostgreSQL.
⚙

Development

Define the structure of the data (the schema).

📄

App development

Build forms, reports, and web pages on the data.

🔍

Interrogation

Let users query the data and get answers (see the SQL demo).

🔄

Maintenance

Add, update, and correct data as the business changes.

06 / Structures

Comparing the structures

No structure is best at everything. Here is the trade-off, in plain terms.

StructureGood atWeak at
Hierarchical+ Fast for fixed, routine transactions− Cannot do many-to-many links
Network+ More flexible than hierarchical− Poor at ad hoc questions
Relational+ Easy questions, easy to maintain− A bit slower than the older models
Multidimensional+ Superb for OLAP analytics− Built for analysis, not transactions
Object-Oriented+ Handles images, audio, video− More complex to design
07 / Structures

Building and governing a database

Databases do not appear by accident. People design them, document them, and protect them.

👨‍💼

DBA

The Database Administrator owns the database and guards its integrity and security.

⚙

DDL

Data Definition Language: the commands used to define the structure (the schema).

📖

Data dictionary

"Data about the data" (metadata): definitions, rules, who can access what.

🕸

ER diagram

A map of the entities and how they relate, drawn before building.

Two views of the same data: the logical view is how a user sees it (a tidy table). The physical view is how it is really stored on disk. The DBMS translates between them, so users never worry about the hardware.
08 / Types & analytics

Types of databases

Different jobs need different databases. These are the main families.

💾

Operational

The live data that runs daily work: customers, inventory, HR. Also called transaction or production databases.

🌐

Distributed

Copies or parts of a database kept on servers in several locations for speed and safety.

🔗

External

Data you access from outside, often paid: web services, search engines, statistics providers.

🎬

Hypermedia

Linked pages of multimedia (the web itself) rather than rows of records.

🏭

Data warehouse

Cleaned, historical data gathered for analysis and decisions (covered next).

📊

Data mart

A smaller slice of a warehouse focused on one department or process.

Distributed: two ways to stay in sync. Replication finds and copies every change to all sites (current but complex). Duplication copies one master after hours (simple but the copies lag).

10 / Types & analytics

The OLAP cube

A multidimensional database lets managers look at numbers from several angles at once, like a cube. Each side is a dimension (Product, Region, Time) and each cell holds a number (like sales).

OLAP = Online Analytical Processing. "Slicing and dicing" means picking one side of the cube to get a simpler view, with no new query written from scratch.

13 / Wrap up

Real-world case: opening the data vault

When data is treated as a managed resource, it can become a product in itself. Three giants opened parts of their databases to outside developers.

🛒

Amazon

~10 years and $1bn to build its data vault. Opened in 2002; 65,000+ developers and businesses tapped in, many became partners.

🌐

eBay

Opened its $3bn databases in 2003. 15,000+ developers registered, 1,000+ apps appeared, 41% of listings uploaded via them.

🔍

Google

Cautious: 1,000 free search results a day, more by permission. Opened AdWords to outside apps in 2005.

Discussion question: should every company open its databases to outsiders? Weigh the new revenue and innovation against the risk of losing control of a core asset.
14 / Wrap up

Key takeaways

1. Manage data as a resource

Treat data as a strategic asset that serves the whole business.

2. Database beats file processing

Sharing one database removes redundancy and adds integration, independence, and integrity.

3. Relational is the default

Linked tables are the standard; cubes (multidimensional) power analytics.

4. Warehouse, then mine

Clean historical data feeds mining, OLAP, and decision support.

5. The DBMS is the engine

It develops, maintains, and interrogates databases; SQL is the query standard.

6. Govern the data

DBAs, data dictionaries, and security keep data accurate and safe.

15 / Wrap up

Quick glossary

DBMS

Software between users and the database. Creates, maintains, and queries data.

Schema

The defined structure of a database: its tables, fields, and relationships.

Field / Record / Table

A fact / one entity fully described / many records of the same kind.

Primary & foreign key

The unique ID of a row, and the field that links one table to another.

Metadata

Data about data: definitions, rules, and access info in the data dictionary.

Data warehouse / mart

A clean historical store for analysis / a focused subset of it.

OLAP

Online Analytical Processing: fast slice-and-dice analytics on a cube.

Data mining

Finding hidden patterns and relationships in large data pools.

SQL

Structured Query Language: the standard way to query relational data.

ETL

Extract, Transform, Load: the pipeline that fills a data warehouse.
